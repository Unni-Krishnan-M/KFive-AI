# Roadmap

- Phase 0 — Audit: completed 2026-08-23.
- Phase 1 — Repository stabilization: code/configuration slice completed; live Compose/E2E verification pending.
- Phase 2 — Runtime/provider configuration: provider-neutral adapters, validated topology, and Settings connection APIs/UI are implemented and locally tested; external provider and live Compose E2E remain pending.
- Phase 3 — Core AI: model catalog/management, GPU probing, and smart routing are implemented and locally tested; host Ollama/GPU E2E remains pending.
- Phase 4 — Project Rooms: owner-scoped persistence, lifecycle, activity, deletion safeguards, and initial project-context links are implemented and locally tested; Mongo/browser E2E remains pending.
- Phase 5 — Code Lab: API/UI, persistent queue state, disposable-container broker, limits, cancellation, recovery, stale cleanup, and opt-in Compose wiring are implemented and source-tested. State remains Experimental until the target-host Docker isolation suite passes and runtime images are pinned by digest.
- Phase 6 — Document Studio: browser-local PDF merge/extract/rotate plus document-route safety hardening are implemented and source-tested. State remains Experimental until browser download smoke testing; isolated server processing and the remaining utilities are planned.
- Phase 7 — Document AI and RAG: a bounded TXT/Markdown Knowledge/RAG vertical slice is implemented and source-tested. State remains Experimental until the live ChromaDB + embedding-provider ingestion/query/delete/persistence path passes; PDF/OCR document intelligence remains planned.
- Phase 8 — Repository Intelligence: a deterministic, read-only, project-aware ZIP analyzer vertical slice is implemented and source-tested. State remains Experimental until the live browser/Mongo persistence and target-host hostile-archive resource paths pass; GitHub/local-directory adapters, repository RAG, and deeper AI/security analysis remain planned.
- Phase 9 — Agent Runtime: owner-scoped persistent runs, SSE output, cancellation, periodic stale-run reconciliation, paginated history/detail UI, terminal-run deletion, and bounded audit timelines are implemented in source. State remains Experimental until the target-host provider/Mongo/browser path passes. Tools and approvals are not implemented; execution coordination and retention enforcement remain single-process.
- Phase 10 — Experimental Workflows: implementation is in progress for owner/project-scoped definitions and a server-validated fixed `Input -> Prompt -> LLM -> Output` graph with provider-neutral SSE text, cancellation, bounded persistent history/detail, and terminal-run deletion. It is not a general automation engine: tools, shell/code execution, agents, RAG, documents/OCR, arbitrary nodes, and executable model output are excluded. State remains Experimental through source completion and target-host browser/provider/Mongo E2E. Execution is one process-local run per owner; the 100-definition and 500-run count-then-create retention checks are non-atomic across replicas. Workflow and Agent leases remain separate rather than a shared GPU job queue.
- Phases 11–15 — Planned. See the master product specification; a phase advances only after its critical path executes successfully.

Immediate sequence: finish the bounded Phase 10 source integration without widening its fixed graph → recover the stale local MongoDB volume and execute local persistence/provider/Repository Analyzer E2E → run the live Knowledge/RAG path with an explicitly installed embedding model → run and harden the target-host Code Lab isolation suite → browser-smoke the PDF utilities → execute the Phase 9 and Phase 10 provider/Mongo/browser run, persistence, restart, timeout, cancellation, pagination, and deletion paths. Distributed agent/workflow execution, atomic quota enforcement, age-based/bulk retention controls, and reviewed tool/approval boundaries remain later work.
