# Roadmap

- Phase 0 — Audit: completed 2026-08-23.
- Phase 1 — Repository stabilization: code/configuration slice completed; local Compose health and Notebook restart persistence are verified, while the broader Phase 1 E2E matrix remains pending.
- Phase 2 — Runtime/provider configuration: provider-neutral adapters, validated topology, and Settings connection APIs/UI are implemented and locally tested; live Settings/provider switching and external-provider E2E remain pending.
- Phase 3 — Core AI: model catalog/management, GPU probing, and smart routing are implemented and locally tested; host Ollama/GPU E2E remains pending.
- Phase 4 — Project Rooms: the owner-scoped core lifecycle, activity, deletion safeguards, project-document archive boundary, restart persistence, and second-user isolation passed production-Compose browser/MongoDB verification. State remains Experimental while export/import, cross-resource orphan/cascade policy, and the complete associated-feature matrix remain incomplete.
- Phase 5 — Code Lab: the supported Python/JavaScript critical path is Complete after real browser run/cancel traversed Redis, the worker, disposable Docker execution, MongoDB history, and restart persistence. Additional requested languages and immutable runtime-image digests remain follow-up scope and are not part of that completion claim.
- Phase 6 — Document Studio: six browser-local structural PDF utilities are Implemented with documented limits. Isolated PDF text extraction plus bounded English PNG/JPEG/scanned-PDF OCR passed production API/browser/restart paths. Overall Document Studio remains Experimental because conversion, previews, searchable PDFs, queues/batch processing, and the remaining utilities are planned.
- Phase 7 — Document AI and RAG: bounded TXT/Markdown plus completed stored PDF/OCR Knowledge/RAG paths passed real Ollama/Chroma/Mongo/browser verification with conservative page references and restart persistence. State remains Experimental; durable background indexing/recovery, DOCX/repository ingestion, reranking, searchable PDFs, structured document intelligence, and broader document AI remain planned.
- Phase 8 — Repository Intelligence: the deterministic, read-only ZIP analyzer passed production-Compose browser upload/export, scope/archive guards, second-user rejection, traversal rejection, Mongo restart persistence, deleted-project report recovery, and deletion. State remains Experimental while isolated parsing, target-host hostile-resource proof, and history pagination remain pending; GitHub/local-directory adapters, repository RAG, and deeper AI/security analysis remain planned.
- Phase 9 — Agent Runtime: the local single-replica critical path is Implemented after real production-browser Ollama success/cancel, Mongo history/deletion, and backend-restart persistence passed. Overall Agents remain Experimental: tools and approvals are not implemented, and execution coordination/retention enforcement remain process-local without distributed, remote, or Kubernetes acceptance.
- Phase 10 — Experimental Workflows: the local single-replica critical path is Implemented for the server-validated fixed `Input -> Prompt -> LLM -> Output` graph after real production-browser Ollama success/cancel, Mongo history/deletion, and backend-restart persistence passed. Overall state remains Experimental: this is not a general automation engine, and additional nodes, project/archive live acceptance, distributed coordination, remote providers, and Kubernetes remain pending. Execution is one process-local run per owner; the 100-definition and 500-run count-then-create retention checks are non-atomic across replicas. Workflow and Agent leases remain separate rather than a shared GPU job queue.
- Phase 11 — AI Engineering Lab: Dataset Lab's core browser/auth/MongoDB/filesystem lifecycle, restart persistence, archive behavior, scope separation, and second-user isolation passed live; hostile-resource tests and several requested analysis/ML features remain. Fixed-suite Model Benchmarks passed one real browser-to-Ollama/Redis/worker/Mongo six-call run plus cancellation, export, completed-run restart persistence, scope separation, and archive guards; standard host/GPU/remote/second-user/active-recovery paths remain. Notebook Mode has authenticated editing, durable Mongo/BullMQ runs, a portless opt-in broker, disposable Python execution, removal-before-independent-verification, cancellation, history, worker health/lease controls, and locally executed restart persistence. The phase remains Experimental until immutable dependency/image locking, AppArmor-host hardening, horizontal fencing, remote/Kubernetes proof, and broader worker/browser coverage. ML experiments/training, Python/AI dataset transformations, and a general shared GPU queue remain Planned.
- Phase 12 — Infrastructure: **Experimental**. A bounded local kind core now deploys frontend, backend, MongoDB, Redis, ChromaDB, and Traefik with private data services, persistent claims, probes/resource/security controls, default-deny NetworkPolicies, and a hardened Unix-socket bridge to loopback-only host Ollama. Live ingress/auth/Socket.IO/Phi3 streaming, bridge restart, Mongo/backend restart persistence, and a declared allowed/denied network graph passed. The phase is not complete: worker services, GPU proof, TLS, portable storage/backup, multi-node/remote CNI acceptance, and browser acceptance with local DNS remain.
- Phase 13 — Experimental observability and GitOps slices. Opt-in local-kind Prometheus/Grafana passed backend scrape, browser dashboard, restart persistence, backend-process MongoDB/Redis availability, independent fixed-target MongoDB/Redis/ChromaDB reachability, explicit CPU-only GPU-unavailable telemetry, and backend/subsystem alert firing/recovery lifecycles with browser-visible state. Private Alertmanager passed outage recovery plus authenticated, fingerprint-correlated firing/resolved delivery to a transient in-cluster receiver while the committed baseline remains null-routed. Tokenless Fluent Bit plus private Loki passed tag-derived structured search, Loki/PVC restart persistence, sink-outage recovery, collector restart, and a real browser logs panel under default-deny policy. A separately opt-in secret-backed Datadog overlay passed one correlated authenticated gzip `/api/v2/logs` delivery plus dual-Loki search against a private in-cluster receiver; real Datadog SaaS acceptance remains unverified. Separate Argo CD infrastructure/application Applications passed ordered exact-commit sync, self-heal, bounded pruning, controller restart, core acceptance, and PVC/Secret preservation. Deep datastore/queue metrics and performance, provider/worker reachability, real GPU/DCGM acceptance, production-durable remote log storage/backup, operational paging/escalation, remote Git/cluster proof, and production GitOps hardening remain Planned.
- Phase 14 — **Experimental foundation**. Standalone production Compose provides a loopback-only inner edge, private application/data networks, separate provider egress, stable volumes, resource/security bounds, strict mode-0600 configuration preflight, authenticated remote-provider configuration, digest-only image references, and offline same-datastore-image application recovery into fresh volumes. Local drills passed provider streaming, recreation persistence, recovery of Mongo identity/dataset bytes/Redis state/raw Chroma content, and a same-host Hybrid provider outage/recovery contract. A separate operator-managed Nginx cell passed strict private-CA/hostname TLS, fixed-origin routing, forwarding-spoof resistance, authenticated SSE, restart persistence, and exact cleanup. Public DNS/trust and certificate lifecycle, real registry artifacts, a clean remote host/provider, authenticated/encrypted off-host retention, cross-host migration, remote monitoring, and laptop-independence remain Planned.
- Phase 15 — **Experimental**. Default-deny local-kind NetworkPolicies and production-Compose recovery passed. Bounded security work now enforces bcrypt byte limits, a ten-session cap, Mongo compare-and-swap rotation, and Implemented local browser refresh, natural access-expiry/recovery, hash-exact cleanup of correctly presented expired refresh sessions, exact presented-predecessor revocation during browser login/registration replacement, plus two-tab Chromium/Web Locks coordination. The auth paths use an HttpOnly/Secure/Strict `__Host-` cookie, exact-Origin/token-bound CSRF, explicit access/refresh token types and distinct signing keys, bounded canonical lifetimes, an origin-wide mutation lock, monotonic state, per-login lineage against cross-session replay, hash-absent stale-replay safety, restart recovery, and logout refresh revocation. Production dependency audit highs fell from two to zero; authenticated-read performance and Hybrid provider outage/recovery cells also passed. These remain local proofs, not tenant isolation, complete identity/account lifecycle, early access-token revocation, background expired-session sweeping, no-Web-Locks/broader-browser or crash-transparent behavior, transactional cross-account replacement, all-session/token-family revocation, sustained/mixed or multi-user sizing, remote CNI/DR, Kubernetes recovery, or production certification. Broader security/performance review and the real remote-host acceptance cell remain incomplete.

Immediate sequence: isolate and resource-test Repository Analyzer parsing and add history pagination → extend Notebook Mode with immutable dependency/image locking and an AppArmor-capable host proof → finish Model Benchmark host/GPU/remote/second-user/active-recovery/limit paths → add durable RAG indexing recovery and pagination → extend Workflows only through separately reviewed vertical slices. Distributed agent/workflow execution, transactional notebook fencing for multiple workers, atomic quota enforcement, age-based/bulk retention controls, hostile Dataset resource proof, and a general shared GPU queue remain later work.
