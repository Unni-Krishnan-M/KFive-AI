# Roadmap

- Phase 0 — Audit: completed 2026-08-23.
- Phase 1 — Repository stabilization: code/configuration slice completed; local Compose health and Notebook restart persistence are verified, while the broader Phase 1 E2E matrix remains pending.
- Phase 2 — Runtime/provider configuration: provider-neutral adapters, validated topology, and Settings connection APIs/UI are implemented and locally tested; live Settings/provider switching and external-provider E2E remain pending.
- Phase 3 — Core AI: model catalog/management, GPU probing, and smart routing are implemented and locally tested; host Ollama/GPU E2E remains pending.
- Phase 4 — Project Rooms: the owner-scoped core lifecycle, activity, deletion safeguards, project-document archive boundary, restart persistence, and second-user isolation passed production-Compose browser/MongoDB verification. State remains Experimental while export/import, cross-resource orphan/cascade policy, and the complete associated-feature matrix remain incomplete.
- Phase 5 — Code Lab: API/UI, persistent queue state, disposable-container broker, limits, cancellation, recovery, stale cleanup, and opt-in Compose wiring are implemented and source-tested. State remains Experimental until the target-host Docker isolation suite passes and runtime images are pinned by digest.
- Phase 6 — Document Studio: the current browser-local PDF merge/extract/rotate surface passed production-Compose real-auth download and output-byte verification, and document-route safety is hardened. Those three utilities are Implemented; overall Document Studio remains Experimental because isolated server processing and the remaining utilities are planned.
- Phase 7 — Document AI and RAG: a bounded TXT/Markdown Knowledge/RAG vertical slice is implemented and source-tested. State remains Experimental until the live ChromaDB + embedding-provider ingestion/query/delete/persistence path passes; PDF/OCR document intelligence remains planned.
- Phase 8 — Repository Intelligence: a deterministic, read-only, project-aware ZIP analyzer vertical slice is implemented and source-tested. State remains Experimental until the live browser/Mongo persistence and target-host hostile-archive resource paths pass; GitHub/local-directory adapters, repository RAG, and deeper AI/security analysis remain planned.
- Phase 9 — Agent Runtime: owner-scoped persistent runs, SSE output, cancellation, periodic stale-run reconciliation, paginated history/detail UI, terminal-run deletion, and bounded audit timelines are implemented in source. State remains Experimental until the target-host provider/Mongo/browser path passes. Tools and approvals are not implemented; execution coordination and retention enforcement remain single-process.
- Phase 10 — Experimental Workflows: an owner/project-scoped source slice is implemented for the server-validated fixed `Input -> Prompt -> LLM -> Output` graph with provider-neutral SSE text, cancellation, bounded persistent history/detail, and terminal-run deletion. It is not a general automation engine: tools, shell/code execution, agents, RAG, documents/OCR, arbitrary nodes, and executable model output are excluded. State remains Experimental until target-host browser/provider/Mongo E2E. Execution is one process-local run per owner; the 100-definition and 500-run count-then-create retention checks are non-atomic across replicas. Workflow and Agent leases remain separate rather than a shared GPU job queue.
- Phase 11 — AI Engineering Lab: Dataset Lab's core browser/auth/MongoDB/filesystem lifecycle, restart persistence, archive behavior, scope separation, and second-user isolation passed live; hostile-resource tests and several requested analysis/ML features remain. Fixed-suite Model Benchmarks passed one real browser-to-Ollama/Redis/worker/Mongo six-call run plus cancellation, export, completed-run restart persistence, scope separation, and archive guards; standard host/GPU/remote/second-user/active-recovery paths remain. Notebook Mode has authenticated editing, durable Mongo/BullMQ runs, a portless opt-in broker, disposable Python execution, removal-before-independent-verification, cancellation, history, worker health/lease controls, and locally executed restart persistence. The phase remains Experimental until immutable dependency/image locking, AppArmor-host hardening, horizontal fencing, remote/Kubernetes proof, and broader worker/browser coverage. ML experiments/training, Python/AI dataset transformations, and a general shared GPU queue remain Planned.
- Phases 12–15 — Planned. See the master product specification; a phase advances only after its critical path executes successfully.

Immediate sequence: extend Notebook Mode with immutable dependency/image locking and an AppArmor-capable host proof → finish Model Benchmark host/GPU/remote/second-user/active-recovery/limit paths → run live Repository Analyzer and Knowledge/RAG paths → run and harden Code Lab isolation → execute the Phase 9 and Phase 10 provider/Mongo/browser paths. Distributed agent/workflow execution, transactional notebook fencing for multiple workers, atomic quota enforcement, age-based/bulk retention controls, hostile Dataset resource proof, and a general shared GPU queue remain later work.
