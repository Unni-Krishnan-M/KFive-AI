# Security

Do not report security vulnerabilities in public issues. Contact the repository owner privately with impact, reproduction steps, and affected versions.

Current security posture is experimental, not production-certified. Never expose MongoDB, Redis, or ChromaDB publicly. Use random secrets of at least 32 characters, HTTPS for remote deployments, exact CORS origins, and a remote AI endpoint protected by transport/network controls.

Agent Runtime is Experimental and currently has no executable tools. The server rejects non-empty tool lists and sends no tool definitions to the AI provider; model output is text, not authorization to run commands or mutate a system. An approval workflow is therefore not part of the current runtime. Do not enable future read or write tools merely by exposing a provider tool call: require a reviewed server allowlist and schema, owner/project authorization, bounded arguments and results, SSRF/path/command defenses appropriate to the tool, idempotency and retry rules, durable audit events, and explicit approval for consequential writes.

Agent prompts and outputs are application-readable MongoDB data. List endpoints omit them, but authenticated owner-scoped detail endpoints return them. Terminal deletion and the 500-run owner cap bound retained records; they do not provide secure erasure, age-based retention, redaction, encryption at the application layer, or an atomic multi-replica quota. Archived-project history is read-only. Do not put secrets or regulated data in prompts, and use a single backend process for the current execution/cancellation boundary.

Agent prompts and generated outputs are persisted in MongoDB and returned by the authenticated owner-scoped detail API. The Agent record separately stores its system prompt, while a run snapshot retains only the system-prompt hash. The system and user prompts are also sent to the configured AI provider, so a remote provider moves that content off-host. There is no bulk deletion, age-based retention/redaction setting, or application-level field encryption yet. Do not submit secrets or regulated content, restrict provider/database/backup access, and apply storage-level encryption according to the deployment. Agent concurrency and cancellation controls are process-local, so run only one backend replica for this slice; a different replica cannot abort the provider request, and restart recovery records interruption rather than resuming work. Do not expose the runtime as a horizontally scaled production service until distributed leases, durable execution, cross-process cancellation, and target-host provider/Mongo/browser E2E exist.

The Phase 10 Workflow slice is Experimental and still being implemented. Its only accepted graph is the server-validated `Input -> Prompt -> LLM -> Output` chain. It has no tool, shell, code-runner, agent, RAG, document, OCR, action, branch, or arbitrary-node execution. Provider output is inert text even if it resembles code, a tool call, or an instruction; it must never be dispatched or treated as authorization.

Workflow definitions store prompt templates and system prompts as application-readable plaintext. Each run also stores its input and generated output in plaintext and snapshots the full workflow definition, including the template and system prompt. Owner-scoped reads, the 100-definition/500-run caps, and explicit terminal-run deletion do not provide secure erasure, age-based expiry, redaction, application-level field encryption, or an atomic multi-replica quota. The rendered prompt/input and system prompt are sent to the selected provider, so remote-provider execution moves them off-host. Do not submit secrets or regulated data and restrict access to the provider, MongoDB, and backups.

Workflow input, prompt template, and system prompt are each bounded to 16 KiB; generated output is bounded to 256 KiB and execution to 30 seconds. History is limited to 50 summaries per page over at most ten pages, and timelines to 50 events. One workflow run per owner is enforced in process, while both the 100-definition and 500-run caps use non-atomic count-then-create checks that can be exceeded by concurrent requests or replicas. Workflow and Agent execution leases are separate controls: together they do not enforce one shared AI/GPU job per owner or provide a durable shared GPU job queue. Use a single backend process for these Experimental paths until distributed coordination and target-host browser/provider/Mongo E2E exist.

Code Lab is disabled by default and Experimental. Never re-enable browser `eval`/`new Function` or backend-process execution of user code. The opt-in trusted broker uses Docker-daemon access to create disposable non-root runtime containers with no network, capabilities, Docker socket, or host mounts and with fixed CPU, memory, process, temporary-storage, output, and time limits. Docker-daemon access is itself privileged: keep it away from user programs, restrict broker inputs to the fixed execution schema, and prefer a dedicated or rootless daemon. Do not expose Code Lab publicly until the target-host isolation suite passes and the reviewed runtime images are pinned by immutable digest.

Documents remain untrusted. Browser-local PDF utilities enforce filename/media/signature, file-count, byte, page, output, malformed, and encryption limits, but browser isolation is not a multi-tenant server boundary. The backend does not run LibreOffice, Poppler, or another native parser. Keep server conversion disabled until a separate non-root constrained processor has decompression/page/output/time/resource limits, macro and embedded-script handling, isolated temporary storage, and cleanup tests.

Knowledge sources and retrieved chunks remain untrusted. The current RAG slice accepts only bounded UTF-8 TXT/Markdown, rejects control characters in logical source names, keeps metadata owner/project-scoped, fingerprints vector collections by embedding profile, includes owner/scope selectors in Chroma reads and deletes, and post-validates every retrieved record against ready MongoDB metadata. Retrieved text is delimited as untrusted prompt data and must never be treated as tool instructions. Keep ChromaDB private; the application-level checks do not make a publicly exposed vector database safe.

Repository archives remain untrusted. Multer buffers each accepted ZIP in backend RAM before the current analyzer applies lazy entry handling and explicit count/size/ratio/path/time/read limits. It rejects encrypted, multi-volume, nested, ambiguous, special-file, traversal, absolute, backslash, control-character, and colliding names, and reads only bounded `package.json` manifests with CRC32 verification. It does not unpack to disk, run code or scripts, install dependencies, write repository contents, or use the network. The persisted report contains archive-derived paths and sanitized manifest metadata; sensitive-filename signals are narrow heuristics, not secret scanning, malware scanning, dependency resolution, or vulnerability analysis, and MIME/signature/checksum metadata does not establish safety. Parsing and rate/admission state remain process-local; do not expose the Experimental analyzer as a production multi-tenant importer until hostile-archive resource testing passes and parsing is moved to a separately constrained worker/service.
