# Security

Do not report security vulnerabilities in public issues. Contact the repository owner privately with impact, reproduction steps, and affected versions.

Current security posture is experimental, not production-certified. Never expose MongoDB, Redis, or ChromaDB publicly. Use random secrets of at least 32 characters, HTTPS for remote deployments, exact CORS origins, and a remote AI endpoint protected by transport/network controls.

Chat prompts and generated text are application-readable MongoDB data and are sent to the explicitly configured provider. The server commits a bounded user turn before inference, uses a request-id/status compare-and-swap lease, caps prompts at 4,000 characters/16 KiB, recent provider context at 1 MiB, output at 256 KiB, and the embedded history at 64 messages. Provider exceptions are mapped to fixed public errors; raw endpoint responses, causes, and credentials must never be returned through SSE. Timeout, Stop, output-limit, failure, and stale-process interruption become durable terminal states. Browser disconnect and explicit Stop can abort the active provider only in the backend process that owns it, so this Experimental Chat runtime must use one backend replica until cancellation and leases are distributed. Chat has no age-based expiry, secure erasure, field encryption, or complete conversation-deletion control yet. Do not place secrets or regulated data in prompts, and restrict provider, database, volume, and backup access.

Agent Runtime is Experimental and currently has no executable tools. The server rejects non-empty tool lists and sends no tool definitions to the AI provider; model output is text, not authorization to run commands or mutate a system. An approval workflow is therefore not part of the current runtime. Do not enable future read or write tools merely by exposing a provider tool call: require a reviewed server allowlist and schema, owner/project authorization, bounded arguments and results, SSRF/path/command defenses appropriate to the tool, idempotency and retry rules, durable audit events, and explicit approval for consequential writes.

Agent prompts and outputs are application-readable MongoDB data. List endpoints omit them, but authenticated owner-scoped detail endpoints return them. Terminal deletion and the 500-run owner cap bound retained records; they do not provide secure erasure, age-based retention, redaction, encryption at the application layer, or an atomic multi-replica quota. Archived-project history is read-only. Do not put secrets or regulated data in prompts, and use a single backend process for the current execution/cancellation boundary.

Agent prompts and generated outputs are persisted in MongoDB and returned by the authenticated owner-scoped detail API. The Agent record separately stores its system prompt, while a run snapshot retains only the system-prompt hash. The system and user prompts are also sent to the configured AI provider, so a remote provider moves that content off-host. There is no bulk deletion, age-based retention/redaction setting, or application-level field encryption yet. Do not submit secrets or regulated content, restrict provider/database/backup access, and apply storage-level encryption according to the deployment. Agent concurrency and cancellation controls are process-local, so run only one backend replica for this slice; a different replica cannot abort the provider request, and restart recovery records interruption rather than resuming work. Do not expose the runtime as a horizontally scaled production service until distributed leases, durable execution, cross-process cancellation, and target-host provider/Mongo/browser E2E exist.

The Phase 10 Workflow source slice is implemented and Experimental. Its only accepted graph is the server-validated `Input -> Prompt -> LLM -> Output` chain. It has no tool, shell, code-runner, agent, RAG, document, OCR, action, branch, or arbitrary-node execution. Provider output is inert text even if it resembles code, a tool call, or an instruction; it must never be dispatched or treated as authorization.

Workflow definitions store prompt templates and system prompts as application-readable plaintext. Each run also stores its input and generated output in plaintext and snapshots the full workflow definition, including the template and system prompt. Owner-scoped reads, the 100-definition/500-run caps, and explicit terminal-run deletion do not provide secure erasure, age-based expiry, redaction, application-level field encryption, or an atomic multi-replica quota. The rendered prompt/input and system prompt are sent to the selected provider, so remote-provider execution moves them off-host. Do not submit secrets or regulated data and restrict access to the provider, MongoDB, and backups.

Workflow input, prompt template, and system prompt are each bounded to 16 KiB; generated output is bounded to 256 KiB and execution to 30 seconds. History is limited to 50 summaries per page over at most ten pages, and timelines to 50 events. One workflow run per owner is enforced in process, while both the 100-definition and 500-run caps use non-atomic count-then-create checks that can be exceeded by concurrent requests or replicas. Workflow and Agent execution leases are separate controls: together they do not enforce one shared AI/GPU job per owner or provide a durable shared GPU job queue. Use a single backend process for these Experimental paths until distributed coordination and target-host browser/provider/Mongo E2E exist.

Model Benchmarks sends six fixed prompts to the explicitly selected configured model. Remote providers can charge for all six calls and may continue work after KFive requests cancellation. Runs are bounded to 16 KiB output per call, 128 KiB total, and 180 seconds. MongoDB is canonical, BullMQ jobs contain only run ids with attempts set to one, a fenced Redis lease limits global execution, and every worker mutation checks lease fence, unique owner, and Mongo revision. Recovery never retries an uncertain in-flight provider call. The per-owner active-run index is atomic, but retention counting and project mutation coordination are not distributed transactions. The portless worker does not receive API JWT signing keys. MongoDB stores raw model output, provider/model identity, timing, provider-reported usage, and sanitized GPU snapshots in application-readable form. The default Compose worker is not granted GPU access; if enabled later, GPU snapshots remain host-wide observations rather than proof of per-model use. Treat exports and backups as sensitive, and verify provider billing/privacy policy before live use.

Code Lab is disabled by default and Experimental. Never re-enable browser `eval`/`new Function` or backend-process execution of user code. The opt-in trusted broker uses Docker-daemon access to create disposable non-root runtime containers with no network, capabilities, Docker socket, or host mounts and with fixed CPU, memory, process, temporary-storage, output, and time limits. Docker-daemon access is itself privileged: keep it away from user programs, restrict broker inputs to the fixed execution schema, and prefer a dedicated or rootless daemon. Do not expose Code Lab publicly until the target-host isolation suite passes and the reviewed runtime images are pinned by immutable digest.

Documents remain untrusted. Browser-local PDF utilities preflight filename/media/file-count/per-file/aggregate size before reads, read sequentially, and enforce signature, page-expression, page, output, malformed, and encryption limits. Public failures and download names are sanitized. Merge/extract/rotate are structural transformations, not sanitizers; links, actions, attachments, or other active content may survive, so every output remains untrusted. Browser isolation is not a multi-tenant server boundary. The backend does not run LibreOffice, Poppler, or another native parser, has no fake in-process document worker, and reports the missing adapter explicitly. Keep server conversion disabled until a separate non-root constrained processor has decompression/page/output/time/resource limits, macro and embedded-script handling, isolated temporary storage, and cleanup tests. Project-document deletion uses the same mutation lease as archive/restore and rejects archived projects before filesystem or Mongo changes.

Knowledge sources and retrieved chunks remain untrusted. The current RAG slice accepts only bounded UTF-8 TXT/Markdown, rejects control characters in logical source names, keeps metadata owner/project-scoped, fingerprints vector collections by embedding profile, includes owner/scope selectors in Chroma reads and deletes, and post-validates every retrieved record against ready MongoDB metadata. Retrieved text is delimited as untrusted prompt data and must never be treated as tool instructions. Keep ChromaDB private; the application-level checks do not make a publicly exposed vector database safe.

Repository archives remain untrusted. Multer buffers each accepted ZIP in backend RAM before the current analyzer applies lazy entry handling and explicit count/size/ratio/path/time/read limits. It rejects encrypted, multi-volume, nested, ambiguous, special-file, traversal, absolute, backslash, control-character, and colliding names, and reads only bounded `package.json` manifests with CRC32 verification. It does not unpack to disk, run code or scripts, install dependencies, write repository contents, or use the network. The persisted report contains archive-derived paths and sanitized manifest metadata; sensitive-filename signals are narrow heuristics, not secret scanning, malware scanning, dependency resolution, or vulnerability analysis, and MIME/signature/checksum metadata does not establish safety. Parsing and rate/admission state remain process-local; do not expose the Experimental analyzer as a production multi-tenant importer until hostile-archive resource testing passes and parsing is moved to a separately constrained worker/service.

Dataset files and cells remain untrusted. Dataset Lab accepts only authenticated owner/project CSV and flat-object JSON with 5 MiB source, 10 MiB derived-input/output, 10,000-row, 100-column, 16-KiB UTF-8-cell, 50-preview-row, and 500-preview-character bounds. Workspace and project Mongo filters are disjoint, direct reads/downloads/mutations are owner-scoped, and live two-user checks return the same not-found states for missing and differently owned records. The derived limit is separate because serialization and CSV formula escaping can expand the source. Analysis is deterministic Node code for schema, missing/duplicate evidence, numeric/category summaries, IQR signals, and bounded correlations; no Python, shell, model, or AI provider receives the dataset. These limits reduce denial-of-service exposure but do not isolate parsing from the backend event loop or heap. Admission and rate state are process-local, and the 100-record owner quota is non-atomic across concurrent requests and replicas. Keep one backend process and complete hostile CPU/RAM/disk tests before multi-tenant production use.

Notebook source, snapshots, outputs, metrics, and artifacts are application-readable MongoDB data. The API enforces authentication, owner/project scope, immutable project association/snapshots, revision compare-and-swap, archived-project read-only behavior, one active run per owner, and bounded source/history/output contracts. Do not store secrets in cells, and do not mistake authenticated reads, deletion, or backup controls for application-level encryption or secure erasure.

Notebook execution is disabled by default and Experimental when explicitly enabled. Only the portless trusted broker receives Docker-daemon access; that access is effectively host-level authority and must never reach user code. Runtime and verifier containers have distinct non-root UIDs, read-only roots, no network, no IPC sharing, no capabilities, no privilege, no host mounts, no Docker socket, and bounded CPU/RAM/PIDs/tmpfs/time/output. The broker streams strict hash-checked envelopes, removes the user-code runtime before starting the no-user-code verifier, and persists only independently reconstructed inert output. A real canary and host seccomp check gate readiness; AppArmor is required by default. The CachyOS live functional test explicitly disabled AppArmor because that host lacks it, so it is not a production hardening certification. Local tags/transitive dependencies are not digest-locked, and multi-worker execution lacks a Redis/Mongo transactional fence. Use one worker, retain the default AppArmor requirement on capable hosts, prefer a dedicated/rootless daemon, and do not expose this slice as a hardened multi-tenant service yet.

CSV values beginning with formula characters can execute when opened by spreadsheet software. The immutable original is never rewritten. Formula escaping is available only as an explicit derived-copy choice, must preserve a visible distinction from the source, and does not establish that the derived spreadsheet is safe from every application-specific interpretation. Treat all downloaded originals and derived copies as untrusted attachments.

Dataset originals and derived copies are private files in the persistent backend uploads volume; MongoDB contains application-readable metadata, analysis, bounded previews/category values, checksums, and parent/child relationships. Owner-scoped attachment routes and hidden internal storage paths do not provide application-level encryption, malware scanning, regulated-data handling, secure erasure, or protection from host, filesystem, database, or backup operators. Deleting a live record/file does not delete snapshots or backups. A source parent cannot be deleted while derived children remain, and archived-project datasets remain read/download-only until restoration. Restrict storage and backup access, use deployment-level encryption and retention controls, and do not upload secrets or regulated data without an appropriate data-handling design.
