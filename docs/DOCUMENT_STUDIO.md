# Document Studio

Document Studio is being built as local-first PDF utilities plus separately deployable document-processing services. Its current feature state is **Experimental**.

## Current verified browser slice

The **PDF Utilities** page exposes only operations backed by the installed `pdf-lib` implementation:

- merge 2–10 PDFs in explicit file order;
- extract an ordered selection such as `3,1-2` into one new PDF;
- rotate selected pages by 90, 180, or 270 degrees.

These operations execute in the browser. Source files are not uploaded, generated PDFs are offered as downloads, and results are not automatically added to Documents or Projects. The Documents page links to PDF Utilities but explains that the user must select the local source file again.

## Limits and errors

The browser utility validates file count, metadata, `.pdf` filenames, an empty or `application/pdf` media type, and per-file/aggregate byte limits before reading any file content. Files are then read sequentially and checked for the `%PDF-` signature before parsing. Current fixed limits are:

| Limit | Value |
| --- | --- |
| Input file | 25 MiB each |
| Merge aggregate | 75 MiB |
| Merge inputs | 2–10 files |
| Pages per operation | 500 |
| Generated output | 100 MiB |

Encrypted/password-protected and malformed PDFs fail with stable, non-parser-specific messages. Page selections are one-based, preserve the requested order, de-duplicate repeated pages, and support `all`.

Page expressions are additionally bounded to 4,096 characters and 500 tokens. Unexpected internal errors are replaced with one fixed public message, and generated filenames are normalized, length-bounded, and stripped of path separators, control characters, and bidirectional controls.

Automated tests generate PDFs, execute each operation, reload the generated bytes, and verify structure, ordering, page count, rotation, input immutability, pre-read limits, sequential reads, safe filenames/errors, and failure branches. A production-Compose real-auth browser run selected fixtures, invoked all three controls, clicked the actual Blob download links, and reopened each downloaded output to verify its `%PDF-` bytes, page count/order/dimensions, and rotations. The current three-operation PDF surface is **Implemented**; Document Studio as a whole remains **Experimental**.

## Persistent Documents

Document upload/list records are authenticated and owner/project-scoped. MIME and basic file signatures are validated, filenames are sanitized, and random internal filenames are used. API responses expose only public metadata—never internal storage paths, internal filenames, stored content, user IDs, or raw processor errors.

There is no Document Processor adapter or API-process worker. An accepted upload is persisted once with the fixed `Document processor is unavailable` failed state; Settings also reports that the dependency is unavailable even if an unused endpoint variable is present. It does not claim extraction, vectorization, RAG, or document chat. Native server conversion returns `503 DOCUMENT_PROCESSOR_UNAVAILABLE`.

## Security boundary

Untrusted PDF and Office parsing must not run in the backend API process. A future deployable Document Processor must use its own non-root container, read-only filesystem, isolated temporary workspace/tmpfs, no unnecessary network, fixed tool and argument allowlists, and CPU/RAM/PID/time/page/input/output limits. Cleanup must cover success, parser failure, timeout, cancellation, and service restart.

Merge, extract, and rotate are structural transformations, not sanitizers. They may preserve links, actions, attachments, or other active content from an input PDF. The UI warns that every generated file remains untrusted.

LibreOffice/Office conversion should remain an optional heavy profile. Password protection/decryption requires a reviewed tool such as qpdf and must never bypass authorization. Compression/rendering/text extraction need separately tested native tooling and must not be inferred from the current structural PDF slice.

## Planned operations

Preview/thumbnails, split-to-multiple-files, reorder/delete/duplicate pages, compression, page numbers, watermark, images-to/from-PDF, text/Markdown/Office conversion, batch jobs, protection, OCR, structured extraction, summaries, comparison, and RAG are Planned until their real paths and failure cases are executed.
