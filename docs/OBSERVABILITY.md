# Observability

State: **Experimental**.

KFive now has a bounded, opt-in local-kind observability slice. The backend exports Prometheus-format HTTP/process, MongoDB/Redis connection-availability, and backend-process GPU-probe metrics at the cluster-internal `/metrics` endpoint. A separate fixed-target prober independently checks MongoDB/Redis TCP reachability and ChromaDB's HTTP heartbeat without accepting caller-selected targets. Prometheus `v3.14.0` scrapes both private endpoints and retains at most 24 hours or 512 MiB on a protected 2 GiB persistent claim. Alertmanager `v0.29.0` receives alerts over a private ClusterIP and retains at most 24 hours on a protected 512 MiB claim; its committed route is a null receiver with no outbound notification. Grafana `13.2.2` provisions private Prometheus and Loki datasources and a read-only **KFive Overview** dashboard containing request-rate, memory, application-log, dependency, GPU-state, independent-probe, and firing-alert panels.

Fluent Bit `5.1.2` runs as a non-root DaemonSet and tails only `kfive` namespace container logs. It parses CRI records, nests JSON application fields under `structured`, derives namespace/pod/container/Docker identity from the log tag, and sends records to private single-binary Loki `3.7.8`. Kubernetes labels and annotations are disabled. Loki uses TSDB v13 and filesystem storage on a protected 2 GiB claim with 24-hour compactor retention. Ingestion rate/burst, per-stream rate, line size, query lookback/length/parallelism, result count, and dashboard lines are explicitly bounded. Only the fixed `job`, `namespace`, and `container` labels are indexed; request ids, paths, pods, users, and arbitrary Kubernetes labels remain line content.

Fluent Bit uses the default ServiceAccount with token automount disabled and has no Role or RoleBinding; tag-derived metadata requires no Kubernetes API access. In the default profile it has no Service, Ingress, external output, runtime socket, or writable host mount. Its retry/tail database uses a bounded ephemeral volume: temporary sink outages can recover while the collector remains available, but node or collector loss can discard unflushed records. Loki and Prometheus are private ClusterIP services with no direct Traefik route. Loki has no service-account token, and analytics plus automatic service/log-level label discovery are disabled.

The separate `k8s/observability-datadog` overlay retains Loki and adds a bounded Datadog output. The real endpoint profile uses TLS and gzip and reads `DD_API_KEY` from an externally created `kfive-datadog` Secret; the key is not committed or put in a ConfigMap. Enabling this profile is an explicit data-egress decision because all collected `kfive` logs are also sent to the configured provider. Its NetworkPolicy permits the collector to reach any destination on TCP/443 because standard NetworkPolicy cannot match an FQDN; production needs an FQDN-aware CNI rule or controlled egress proxy.

Application route labels and ordinary request/error logs use matched route templates under a static mount allowlist. All 404s collapse to `/not-found`, unsupported shapes collapse to `/unknown`, and raw path/query values do not become metrics or routine request-log fields. Backend logs and metrics do not record authorization headers or query parameters. Traefik's raw `RequestPath` access-log field is dropped because it includes query strings. A live canary found neither a supplied Authorization value nor query token in Loki. Grafana is exposed only through the loopback local-kind Traefik file-provider route and permits anonymous Viewer access; basic login, sign-up, plugin administration, plugin auto-updates, and update reporting are disabled for this immutable local profile.

GPU probing is cached for 15 seconds and single-flight. An available sample is validated, capped at eight numeric device indices, and exposes aggregate/per-index VRAM, utilization, and temperature. Names, UUIDs, drivers, raw diagnostics, models, users, projects, runs, URLs, and credentials are excluded. An unavailable probe emits availability `0`, device count `0`, and one fixed reason while omitting per-device series. The local kind backend intentionally has no GPU device mapping, so its verified `nvidia-smi-not-found` state proves honest unavailability handling, not that the host has no GPU or that hardware telemetry works.

## Run and verify

```bash
npm run test:observability
npm run kind:up:observability
# map kfive.local to 127.0.0.1 in local DNS or /etc/hosts for a normal browser
npm run kind:verify:observability
npm run kind:verify:probes
npm run kind:verify:logs
npm run kind:verify:alerts
npm run kind:verify:network-policies
npm run kind:down
```

To enable the external Datadog output, put a real `DD_API_KEY` in the private, ignored `.env` file and start a fresh disposable profile:

```bash
npm run kind:up:datadog
```

This command validates the key before cluster creation, injects it from a mode-0600 temporary file, and does not print it. Verify the collector integration safely without contacting Datadog by starting the ordinary observability profile and then running `npm run kind:verify:datadog`. That verifier substitutes a private ClusterIP receiver, proves authenticated gzip plus same-marker Loki delivery, restores the default profile, and refuses to run if its Secret, Service, or Deployment names already exist. Do not run it against a cluster that is intentionally using the real Datadog Secret.

The metrics live verifier checks backend metric content internally, confirms public `/metrics` resolves to the frontend rather than Prometheus, requires MongoDB/Redis availability at `1`, requires explicit CPU-only GPU unavailability with no per-device series, generates API traffic, verifies the Prometheus target, datasource and dashboard, restarts Prometheus and requires an identical historical sample, then restarts Grafana and requires both provisioned resources and a non-provisioned PVC marker to survive. A real browser rendered both dependencies as **Available**, GPU probe as **Unavailable**, and VRAM/temperature as **No data**; all datasource calls returned 200. See [the subsystem/GPU record](../output/verification/subsystem-gpu-metrics-live.md).

The independent-probe verifier requires a clean healthy baseline and private-only prober exposure, then scales only ChromaDB to zero. It requires MongoDB and Redis to remain `1`, ChromaDB alone to become `0`, `KFiveSubsystemUnavailable` to fire, and the inverse recovery after ChromaDB is restored. The cleanup path restores the StatefulSet, requires the original PVC UID and application health, and the browser gate renders all three dependencies as **Available**. This is shallow network/heartbeat reachability rather than an authenticated transaction or performance check. See [the subsystem-probe record](../output/verification/subsystem-probes-live.md).

The logging verifier emits a unique structured backend marker and searches for it only through the provisioned Grafana datasource proxy. Before testing external sensitive-value absence, it requires later unique backend and Traefik ingestion watermarks. It proves exact low-cardinality stream labels, private Loki exposure, unchanged PVC identity and historical search after Loki restart, sink-outage recovery, resumed ingestion after collector replacement, and tag-derived metadata with no API token or RBAC. The Datadog verifier separately requires one private-receiver request to correlate the exact path, credential, gzip encoding, and marker, then asserts complete collector restoration without contacting an external service. The NetworkPolicy verifier proves repeated denials from three healthy canaries while the declared telemetry paths stay available. A real Chromium session rendered the 100-line logs panel through repeated 10-second refreshes with zero Grafana restarts; its only console error was the known anonymous Viewer star request returning 401. See [the original observability record](../output/verification/observability-live.md), [the Loki record](../output/verification/loki-live.md), [the Datadog forwarding record](../output/verification/datadog-live.md), and [the NetworkPolicy record](../output/verification/network-policies-live.md).

### KFiveBackendUnavailable

Prometheus evaluates `up{job="kfive-backend"} == 0 or absent(up{job="kfive-backend"})` with a 30-second hold. The rule therefore covers both a failing scrape and a target series that has disappeared. It carries only fixed `severity=critical` and `component=backend` labels. The **Firing alerts** panel is scoped to this alert so unrelated future rules cannot make its recovered value nonzero. `npm run kind:verify:alerts` is destructive only to the disposable profile: it refuses non-baseline or pre-existing harness state; creates a hardened private receiver with a generated bearer-file Secret and exact ingress policy; temporarily routes only this alert to an exact cluster-local URL; holds Alertmanager offline while the rule fires; and requires correlated firing and resolved payloads after recovery. Its `finally` path restores the backend and exact null configuration, explicitly removes the temporary Secret mount/volume, waits for Alertmanager readiness, verifies PVC identity, and removes the receiver policy/Secret/ConfigMap/Service/Deployment. No credential or full payload is printed or retained.

### KFiveSubsystemUnavailable

Prometheus evaluates `kfive_subsystem_probe_success == 0` with a 30-second hold and retains only the fixed `dependency` and `probe` series labels plus fixed `severity=warning` and `component=subsystem` labels. First distinguish a single dependency failure from the prober target being down: check `up{job="kfive-subsystem-probes"}` and the three probe series through the private Prometheus service or Grafana datasource. Then check the affected private Service endpoints and workload readiness in `kfive`; do not expose a datastore or add caller-selected targets to diagnose it. `npm run kind:verify:probes` exercises the Chroma failure and recovery path only on the disposable local-kind profile.

## Current limits

This is not the complete Phase 13 observability design. Only backend HTTP/process metrics, backend-process MongoDB/Redis availability, fixed-target shallow MongoDB/Redis/ChromaDB reachability, one bounded GPU probe, one dashboard, two availability rules, one local authenticated delivery harness, and local-kind restart-persistent logging are implemented. Default-deny policies restrict the verified service graph, but anonymous Viewer access and unauthenticated cluster-internal endpoints remain appropriate only for the loopback single-user profile. This is not tenant isolation: pod selectors are label-based, actors with pod-create/relabel authority can impersonate allowed workloads, and remote/multi-node CNI behavior is unverified. Every Grafana Viewer can query every retained metric and local log.

Loki filesystem storage proves search after pod restart, not survival of kind deletion, node/PV loss, disk exhaustion, or disaster. Retention deletion is asynchronous, not secure erasure, and there is no hard byte-based retention, backup/restore, remote object store, tenant authentication, or multi-replica acceptance. Alertmanager persistence is likewise local-only; the verified receiver is a transient protocol harness, not email/chat/pager delivery, escalation, inhibition, authorized silencing, or on-call acceptance. Fluent Bit's read-only host log mounts remain a privileged trust boundary and its ephemeral queue is not lossless. The optional Datadog path has no real tenant/SaaS, regional endpoint, external TLS-handshake, billing, retention, residency, or legal-policy acceptance; its live proof ends at a private protocol-compatible receiver. Authentication-aware datastore checks, provider/worker reachability, datastore performance, queue depth/latency, kube-state metrics, real GPU runtime/DCGM wiring and controlled hardware load, the broader dashboard/rule set, operational notification receivers, production-durable remote aggregation, TLS, and remote-cluster verification remain Planned. Argo CD has a separate bounded Experimental local-kind slice; it is not a production observability deployment mechanism.
